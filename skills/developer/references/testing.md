# Testing

## Test Files

- Every test file name must include the word `test` — as a prefix or suffix depending on language idioms or the repo's existing layout (e.g. `test_compute_lib.py` vs `compute_lib_test.go`)
- Match the convention already used in the project when one exists

## Test Content

- Write tests for all public functions and methods
- Follow the Arrange-Act-Assert pattern
- Test names should describe the behavior being tested
- Use descriptive test names that explain the scenario and expected outcome
- Keep tests focused and independent
- Test edge cases and error conditions
