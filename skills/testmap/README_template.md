# testmap_output

This folder holds a **testmap** behavioral-coverage audit of the code in the
directory that contains it. The audit covers all source files and subdirectories
within that target directory. Everything here is generated by the skill and is
safe to commit to version control; it can be regenerated by re-running testmap.

## Viewing the report

`report/report.html` is the primary, human-readable report. It loads its data with
`fetch()`, which browsers block on `file://`, so serve this folder over a local web
server and open it through that:

```
python3 -m http.server 8080      # run from this testmap_output/ folder
# then open http://localhost:8080/report/report.html
```

## What's in this folder

| Path | What it is |
|------|------------|
| `report/` | The static HTML report and its bundled assets. Open `report.html` as above. Regenerable; holds no unique data. |
| `index.json` | Every function, method, and class discovered in the target, with location, hashes, complexity, and other metadata. Always the complete symbol set. |
| `triage.json` | Each symbol's risk score and priority bucket (high / medium / low). |
| `analysis.json` | The behavioral analysis per symbol: the behavior matrix of input classes × expected behaviors, each marked covered / gap / unspecified, with covering tests and test prescriptions. The authoritative dataset behind the report. |
| `metrics.json` | The composite score, grade, and headline KPI aggregates shown in the report. |
| `meta.json` | Run-specific details: when the analysis ran, the target's git commit, the scope analyzed, and tool versions. |
| `report_content.json` | The narrative summary and insights written for the report. |
| `mutation.json` | Mutation-testing results per symbol — present only if mutation testing was run. |

For when and how a particular run was performed, see `meta.json`.

meaningfully verifies behavior — not just whether it executes code.
